# Claude ⇄ GPT 项目交接

目标：用户在 Claude（聊天界面、Claude Code）和 GPT（ChatGPT、Codex）之间切换时，项目进度不丢。

核心思路（沿用 `project-handoff-setup`）：

- **本地项目文件夹是唯一的真相来源**：项目根目录（默认 `D:\Projects`）下每个项目一个“两位编号_项目名”文件夹，交接记录在 `notes\交接记录.md`。
- **两边用同一份交接记录、同一套口令**：“开始”、“交接”、“新建项目：xxx”。
- **同一时间只有一个 AI 在做**：交接记录顶部有“当前状态”，开始时标记占用，交接时释放。

各工具怎么读到交接记录：

| 工具 | 读写方式 | 自动读取的规则 |
|---|---|---|
| Claude 聊天界面 | Basic Memory（MCP） | 账号的 Instructions for Claude |
| Claude Code | 直接读写项目文件夹 | `<ROOT>\CLAUDE.md` |
| Codex（CLI / IDE / 应用） | 直接读写项目文件夹；也可用 Basic Memory | `~\.codex\AGENTS.md` |
| ChatGPT 聊天（网页 / 应用） | 默认不能读本地文件，用“复制交接块”中转 | 个性化设置里的自定义指令，或 ChatGPT 项目的指令 |

始终用部署时选定的语言与用户沟通，说明简单直白（用户不是专业开发者）。不覆盖、不删除用户已有的文件和配置；改配置前先备份。

## 一、部署

原则同 `project-handoff-setup`：**开头一次问完、一次申请完权限，之后全部自动完成**。

### 阶段 0：检查并一次性提问

1. 调用 `get_device_info`。
2. 读取 `<ROOT>\CLAUDE.md`（默认找 `D:\Projects\CLAUDE.md`）：
   - 存在 → Claude 侧已部署，从中读出 LANG 和 ROOT，不再询问。
   - 不存在 → 告诉用户需要先部署 Claude 侧，按 `project-handoff-setup` 的流程完成后再继续（它已包含语言、根目录、权限、安装）。
3. 用**一次** AskUserQuestion 问：用户在 GPT 这边用哪些？（多选）
   - Codex（能直接读写电脑上的文件，推荐用来写代码）
   - ChatGPT 聊天（网页或应用）

### 阶段 1：一次性申请权限

告诉用户：“接下来会弹出权限请求，允许后我会自动完成，不再需要你操作。”

- 用 `device_request_folder_access` **一次**申请：ROOT；选了 Codex 时再加 `C:\Users\<用户名>\.codex`（这个文件夹不存在，说明 Codex 还没装或从没运行过：只申请 ROOT，Codex 部分记入最后的手动清单，提醒用户先安装并运行一次 Codex，再说“部署 Claude 和 GPT 交接”补上）。

### 阶段 2：自动部署（不再提问）

用任务列表跟踪，每步完成后自行检查。

**2.1 升级交接记录格式（两边共用）**

对 ROOT 下每个项目的 `notes\交接记录.md`：先暂存（`device_stage_files`），在顶部 `# 交接记录：...` 下面插入“交接状态”一节（模板见下），已有内容一字不动，再写回（`device_commit_files`，带 `expectedMtimeMs`）。已有这一节的跳过。

**2.2 更新 Claude 侧规则**

暂存 `<ROOT>\CLAUDE.md`，在末尾追加“与 GPT 交接”一节（模板见下），写回。已有该节的跳过。

**2.3 Codex（选了才做）**

- 写入 `~\.codex\AGENTS.md`：不存在就用模板新建；已存在就在末尾追加模板内容（按 LANG 翻译，替换 ROOT），不改原有内容。
- 在 `~\.codex\config.toml` 里加入 Basic Memory（可选但推荐，让 Codex 也能按名字找项目）：暂存原文件，先另存一份 `config.toml.bak`，若没有 `[mcp_servers.basic-memory]` 就在末尾追加：

```toml
[mcp_servers.basic-memory]
command = 'C:\Users\<用户名>\.local\bin\uvx.exe'
args = ["basic-memory", "mcp"]
```

  用单引号字符串，Windows 路径里的反斜杠就不用转义。uvx.exe 不存在（Basic Memory 没装）就跳过这一步，记入报告。

**2.4 ChatGPT 聊天（选了才做）**

- 生成 `<ROOT>\GPT指令.txt`：ChatGPT 自定义指令全文（模板见下，按 LANG 翻译，替换 ROOT）。
- 能用电脑操作时，用 `computer_write_clipboard` 把它放进剪贴板。

### 阶段 3：收尾

一条消息告诉用户还需要亲手做的事（只列适用的）：

1. **Codex**：重开 Codex，它就会读到新的 AGENTS.md。在 ROOT 文件夹里启动 Codex（或在 Codex 应用里打开 ROOT），说“开始”。
2. **ChatGPT 聊天**：设置 → 个性化 → 自定义指令，粘贴剪贴板里的内容（或打开 `<ROOT>\GPT指令.txt` 复制）。也可以为每个项目建一个 ChatGPT 项目，把指令贴进项目指令，并上传该项目的 `交接记录.md`。
3. 附上部署结果、备份文件位置、没能自动完成的步骤。

## 二、日常使用（部署后，Claude 与 GPT 都按这套规则）

### 开始

1. 找到项目，读取 `notes\交接记录.md`。
2. 看“交接状态”：
   - **空闲** → 改成“进行中（<工具名>，<日期时间>）”并保存，然后汇报：上次由谁做到哪、未解决问题、下一步。
   - **进行中，且不是自己** → 提醒用户“上次 <工具> 没有交接就结束了，最新进度可能没写进记录”，问用户是直接接手，还是先回到那边补一次交接。用户确认接手后再改状态。

### 交接

更新交接记录的全部内容（进度、决定、关键文件、未解决问题、下一步、更新日志加一条“日期 · 工具 · 做了什么”），并把状态改回“空闲”，填上“上次交接”和“给下一个 AI 的话”。写到另一个完全不了解情况的 AI 能直接接手的程度。

### ChatGPT 聊天的中转（它读不到本地文件时）

- **Claude → ChatGPT**：用户说“交给 GPT”时，Claude 先正常交接，然后把整份交接记录放进一个代码块，告诉用户：复制它，在 ChatGPT 里说“开始”并粘贴。
- **ChatGPT → Claude**：ChatGPT 在“交接”时输出整份更新后的交接记录（一个代码块）。用户回到 Claude 粘贴，说“接回 GPT 的进度”，Claude 用它覆盖该项目的 `交接记录.md`（覆盖前另存一份 `交接记录.bak.md`），然后照常“开始”。
- 代码、素材等文件：ChatGPT 生成的文件让用户下载后放进项目对应的文件夹，并在交接记录的“关键文件”里写明。

## 模板

### 交接状态（插在每份交接记录标题下面）

```markdown
## 交接状态
- 当前状态：空闲
- 上次交接：（日期时间 · 工具 · 账号）
- 给下一个 AI 的话：（最需要知道的一两句，比如“菜单按钮的点击事件写了一半，在 src\ui\menu”）
```

工具名统一写：Claude 聊天 / Claude Code / Codex / ChatGPT。

### `<ROOT>\CLAUDE.md` 追加的一节

```markdown
## 与 GPT 交接
- 交接记录顶部有“交接状态”。开始时：状态为空闲就改成“进行中（Claude，日期时间）”；若显示其他工具进行中，先提醒我对方可能没交接，问我是否直接接手。
- 交接时：状态改回“空闲”，填写“上次交接”和“给下一个 AI 的话”，更新日志写明工具名。
- 我说“交给 GPT”：先交接，再把整份交接记录放进一个代码块，让我复制给 ChatGPT。
- 我粘贴一份交接记录并说“接回 GPT 的进度”：先把原文件另存为 notes\交接记录.bak.md，再用粘贴内容覆盖 notes\交接记录.md，然后照常开始。
```

### `~\.codex\AGENTS.md`

```markdown
# 项目交接规则（Claude ⇄ GPT 共用）

始终用<LANG>回复我。

我的项目都在 <ROOT>，每个项目一个文件夹，命名为“两位编号_项目名”（如 01_毕业设计），结构为 src（代码）、assets（素材）、docs（文档）、notes（交接记录）。
交接记录在项目的 notes\交接记录.md。Claude 和你会轮流做同一个项目，交接记录是唯一的进度来源。

## 开始工作时（我说“开始”或新会话的第一条消息）
- 当前目录是 <ROOT>：列出所有项目（按编号排序），问我继续哪一个或新建项目。
- 当前目录是某个项目：读取 notes\交接记录.md。
- 看“交接状态”：空闲 → 改成“进行中（Codex，日期时间）”并保存，再告诉我上次由谁做到哪、未解决问题、下一步；显示其他工具进行中 → 提醒我对方可能没交接，问我是否直接接手。

## 我说“交接”时
更新 notes\交接记录.md：当前进度、重要决定及原因、关键文件及作用、未解决的问题、下一步（写到能直接动手）、更新日志末尾加一条（日期 · Codex · 做了什么）；状态改回“空闲”，填写“上次交接”和“给下一个 AI 的话”。写到另一个完全不了解情况的 AI 能直接接手的程度。

## 我说“新建项目：xxx”时
在 <ROOT> 下用下一个编号建文件夹和 src、assets、docs、notes，生成第一份交接记录（含“交接状态”一节）。
```

### ChatGPT 自定义指令（`<ROOT>\GPT指令.txt`）

```
始终用<LANG>回复我。
我在 Claude 和你之间轮流做同一批项目，靠“交接记录”接续进度。

我说“开始”并粘贴一份交接记录时：读完后用几句话告诉我上次由谁做到哪、未解决问题、下一步，再问我这次做什么。若“交接状态”显示另一个工具进行中，提醒我它可能没交接。

我说“交接”时：输出整份更新后的交接记录，放在一个 markdown 代码块里，保持原有结构；更新当前进度、重要决定、关键文件、未解决问题、下一步（写到能直接动手）；“交接状态”改为空闲，填写上次交接（日期 · ChatGPT）和给下一个 AI 的话；更新日志末尾加一条。写到另一个完全不了解情况的 AI 能直接接手的程度。我会把它带回 Claude。

你生成的代码或文件，提醒我下载后放进项目的哪个文件夹（src、assets、docs）。
```

## 不要做的事

- 不覆盖、不删除已有的交接记录、CLAUDE.md、AGENTS.md、config.toml；改动前备份，只做增量修改。
- 不在部署中途向用户提问；处理不了的放进最后的报告。
- 不声称已修改 ChatGPT 或 Claude 的账号设置——这些只能由用户粘贴。

# 本机制作与自动检查

适用于在用户的 Windows 电脑上渲染成片。用户已确认：渲染一律在本机完成，不在云端渲染。下文是已验证的做法，不锁定具体软件版本。

## 工程与分工
- 用一个时间源文件统一定义几何、试验参数、事件时间、音效时点和增益；画面、声音、字幕都从这里取时间。
- 画面渲染、混音、合成成片、封面分别写成独立脚本，只改声音时只需重新混音合成，不用重渲画面。
- 给用户双击运行的 .bat：环境安装、完整渲染、补充素材接入各一个，输出写入同目录日志，方便读取结果。
- 一次只由一方（Claude、GPT 或用户）触发渲染；各方用的是同一套脚本，不要重复运行。GPT 不另做视频预览。

## Windows 注意事项
- Python 用官方安装包，勾选“Add python.exe to PATH”，并关闭“应用执行别名”中的 python.exe 和 python3.exe；依赖装进项目自己的 .venv。
- 中文系统命令行默认编码是 GBK：读取 ffmpeg 等外部程序的输出时按字节读取，再用 UTF-8 解码，不要用 text=True。
- 路径含中文时，素材和字体先用 Python 读成字节，再交给绘图库加载。
- .bat 用 CRLF 换行，echo 文字里不要出现括号，否则会破坏 ( ) 代码块。
- 用多进程并行渲染（进程数约为 CPU 线程数减 2），比单进程快几倍；画面和声音分开渲染。
- 通过文件桥写入用户电脑后，要核对文件大小或修改时间；同名文件重复写入时可能写成旧版本，改用新的暂存文件名再写一次。

## 渲染前自动检查（每次都跑）
- 重叠检查：逐帧记录所有标签的文字框和线条，报告“线压字”和“字叠字”；字幕区单独排除。允许两个标签在同一位置交叉淡化。
- 动效检查：逐帧比较，除字幕外，任何文字单帧位移过大或透明度突变都报出，界面区再做逐帧像素突变检测。报告要逐条判断：连续缓动或划入属于正常，瞬移或闪现必须修正。
- 自动检查只是辅助：色块、图标和人物换姿态仍要抽帧目视，不能替代最终审看。

## 交付核对
核对成片的帧数、时长、分辨率和响度（例如 -16 LUFS / -1.5 dBTP），抽取关键时点画面确认状态与台词一致；保留人声、音效、配乐分轨。只报告实际做过的检查。

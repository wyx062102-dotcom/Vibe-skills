# 知识科普动画系列

当前规范版本：0.5.0。先读 [系列制作规范](references/series-standard.md)。这是用户个人系列的工作规范，不是所有视频通用的定律。

## 范围与任务选择
用户请求的产物决定工作范围：脚本只交付脚本；风格预览只生成概念图；素材只生成资产与交接清单；明确要求制作时才进入动画实现。不要因规范包含全流程就自动执行所有阶段。
不把历史某期的主题、文案、角色、场景、音频路径、时长或资产写为系列常量。用户当次要求优先。

## 工作方式
- 风格与交接：读 [策划与交接流程](references/planning-handoff.md)。先定风格再写脚本，先在聊天展示、确认后定稿整理；明确要求打包即执行当前范围打包，不重复询问。
- 动画声音：读 [动画音效绑定](references/animation-sound.md)。每个承载信息的主要动画必须安排对应音效，与动作共用事件时间，不能只给开场、转场、结尾补声。Claude负责选择授权适用的背景音乐并自动配入视频，动态避让人声；用户已选曲优先。
- 策划或脚本：明确核心问题、真实知识机制、证据来源、理解转折和结尾回扣。人生感悟适合选题时使用，不强迫每条内容升华。
- 美术与动效：以GPT生成贴图的动画为主要制作方式，读 [贴图设计与动画](references/texture-animation.md)。人物采用完整姿态切换，不拆关节、不做骨骼绑定。场景与人物按选题需要选择，机制图形保持可编辑。
- 已有录音或后期交接：读 [音画同步](references/audio-sync.md)，以实际语音建立时间线。
- 单期启动、审片或复盘：读 [工作模板](references/templates.md)，只使用需要的模板。
- 修改长期规范：读 [迭代方法](references/evolution.md)，先把单次意见转成明确问题与候选修订；用户授权修改时实施并记录。

- 多平台发布：读 [双语字幕与平台封面](references/publishing.md)。交付中英文字幕及抖音、小红书、B站、YouTube、X适配封面与发布文案；Skill公开、关注自愿。
- 在用户电脑本地渲染：读 [本机制作与自动检查](references/local-production.md)。渲染只在用户电脑执行，一次只由一方触发。

## 规范维护（用户长期授权）
每个子任务结束时（如成片、一轮审片修改、封面文案），把本次确认的做法与新反馈整理进本规范：对应参考文件、版本号与 [迭代方法](references/evolution.md) 记录同步更新，并推送到用户的 GitHub 仓库 wyx062102-dotcom/vibe-video。单期临时做法标为“试用”或“单期例外”，用户明确表态或被证明有效的才写成“已确认”。推送前先比对线上最新内容，保留他人修改；视频交接记录中注明同步结果。

## 输出前检查
检查分层场景衔接、标签与时间线避让、动作阶段与姿态是否一致；细则见 [贴图设计与动画](references/texture-animation.md)。
除字幕外，画面中所有文字与元素的出现、消失、移动和状态变化都要有动效，不能瞬移或瞬间切换；字幕直接切换即可，不加动画。
检查是否回答开头问题、知识是否准确、类比是否越界、动作是否传递信息、重点是否清楚。只报告实际执行的验证；不得把自动对齐或图片生成效果描述为已人工核验。
技术事实按具体选题查证。参考作品仅借鉴表达原则，不复制其文案和独特图形序列；未完整观看时说明观察范围。
